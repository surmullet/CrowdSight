# Existing crowd-model inventory

## Audit status

This inventory is based on files and documentation present in the sibling `heat_map/` and `uav-crowd-monitoring/` projects as of 2026-09-25. SHA-256 values for locally available weights and tracker profiles were computed from those files. No weights or footage have been copied into CrowdSight. The official [VisDrone privacy and data-protection terms](https://aiskyeye.com/data-protection/) state academic-use-only availability and CC BY-NC-SA 3.0 terms, including a noncommercial restriction. The candidate checkpoint inherits VisDrone training data; commercial deployment or redistribution is therefore blocked pending rights-owner/legal review and any required written permission. Ultralytics' [official license page](https://www.ultralytics.com/license) states that trained/fine-tuned YOLO models are covered by AGPL-3.0 by default and that proprietary/commercial products require either AGPL-compliant release or an Enterprise License. Confirm terms applicable to the exact installed version and intended deployment with the rights owner/legal reviewer. These are operational holds, not legal determinations about derivative works.

Cross-project lineage scan on 2026-09-25 found the matching returned run in `uav-crowd-monitoring/artifacts/e01-finetune-returned/`. The SHA-256 of both `heat_map/models/best.pt` and the UAV pilot's returned `best.pt` is `12824a97e19a747c3f852ca335ca3b4e2bfb60e05770c059154265f7761a4ccc`. Training lineage is therefore partially recovered rather than unknown: the candidate is the E01 pilot's fine-tuned best checkpoint, trained with a mixed Plaza/VisDrone manifest. The run record states that independent target validation was not available, and the VisDrone regression set was previously used by the base model. The Plaza source video used in the diagnostic was also used to create adaptation crops, confirming overlap. Redistribution/use rights for all inherited data/model sources still require review.

## Evidence interpretation

`best.pt` is the same returned fine-tuned pilot-best artifact documented in the UAV project, not an unrelated heat_map-only model. Its immediate pilot lineage is documented, and its Plaza/VisDrone mixture is known. Independent target-site validation and full deployment-use rights are not established. The official VisDrone terms are noncommercial; do not approve this inherited checkpoint for commercial deployment or redistribution until the rights owner/legal reviewer confirms the scope or grants permission. Ultralytics states that trained/fine-tuned YOLO models are under AGPL-3.0 by default and proprietary/commercial products need AGPL-compliant release or an Enterprise License; verify the terms applicable to the exact version and intended deployment. The Plaza source also has [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/) attribution/share-alike conditions recorded in the source project's provenance file. E01 base weights are still unavailable as a direct artifact in CrowdSight. `density_net.pt` is a separate output type and its documented count results require the missing evaluation manifest/report for full verification.

No candidate is established as validated for the intended CrowdSight pilot site. Metrics from different clips, splits, hardware, or protocols must not be presented as controlled comparisons.

## DroneCrowd benchmark status

A fresh scan of the sibling `heat_map/` project found `data/videos/test.mp4`, which its README describes as a user-supplied pipeline input; there are no reviewed labels or evaluation manifest for that clip. The same project contains the DroneCrowd crowd-counting dataset: its local `trainlist.txt` has 82 sequences with annotations, while `testlist.txt` has 30 challenge sequences and no corresponding local annotation files. The official [DroneCrowd repository](https://github.com/VisDrone/DroneCrowd) describes the 82-train/30-test challenge split; the official [VisDrone crowd-counting test guidelines](https://aiskyeye.com/evaluate/test-guidelines/) identify the 30 clips as the challenge test split.

The local `chosen.txt` names six annotated sequences, and `train_density_model.py` explicitly excludes those sequences from DensityNet training. However, the `heat_map/README.md` reports a 36-frame head-to-head comparison on that chosen set that includes the same `best.pt` detector. The raw evaluation report/manifest was not found. Treat that set as previously used for this checkpoint, not as a new locked CrowdSight test. Do not reuse the challenge test split without its permitted annotations, permission evidence, and a complete check of training/source overlap. The current `best.pt` held-out evaluation requirement therefore remains open.
